## Trust boundary

In this PHP / MariaDB stack, the trust boundary is crossed when request data (GET/POST parameters, cookies, or headers) is incorporated into a SQL query string without parameterized preparation. The PHP application receives untrusted input from the HTTP request layer and passes it directly to MariaDB via functions like `mysqli_query()` or `mysql_query()` without using prepared statements or parameter binding. Once the data reaches the query construction phase in PHP, it becomes part of the SQL command sent to MariaDB, where the database engine interprets it as executable code rather than data.

## What an attacker gains from a confirmed CWE-89 here

- **Authentication bypass**: Injection into the `username` parameter on the brute-force page allows an attacker to bypass login credentials by manipulating the SQL WHERE clause (e.g., `admin' --`), gaining unauthorized access to the application.
- **Unauthorized data exfiltration**: Injection into the `id` parameter on the SQL injection page allows an attacker to extract sensitive user records from the database using UNION-based or error-based techniques, revealing usernames, passwords, and other stored information.
- **Blind data extraction**: The boolean-blind vulnerability on the `sqli_blind` endpoint enables an attacker to extract data character-by-character through conditional SQL logic, even when errors are suppressed and no data is directly displayed.
- **Database structure reconnaissance**: An attacker can query `information_schema` to enumerate table names, column names, and database metadata, enabling targeted attacks on other parts of the application.
- **Potential privilege escalation or lateral movement**: Depending on MariaDB user permissions, an attacker may be able to write files to the server filesystem or execute operating system commands via `INTO OUTFILE` or `INTO DUMPFILE` clauses, leading to remote code execution.
